# 使用边界与拓展

> 最后更新：2026-08-16

## 一、当前版本的边界（局限）

1. **电脑必须开机且联网**
   - DSH 跑在你的电脑上
   - 电脑关机、睡眠、断网，服务就不可用

2. **隧道域名会变化**
   - 当前使用 Cloudflare Quick Tunnel
   - 每次重启 `start-dsh.ps1`，隧道域名都会变
   - 用户不能长期记住一个地址

3. **固定域名不能浏览器直连**
   - `your-fixed-domain.de5.net` 只能用于 APP / PWA 的自动发现
   - 浏览器直接 HTTPS 访问固定域名会因 TLS 证书不匹配失败
   - 因为 Quick Tunnel 的证书只覆盖 `*.trycloudflare.com`

4. **每个用户都需要自己的 DSH 服务器**
   - PWA 是通用客户端，只负责连接
   - 用户必须自己部署 DSH + 插件 + 隧道
   - 对普通用户来说，部署门槛仍然偏高

5. **免费隧道带宽有限**
   - 拉取大会话历史时可能较慢
   - 不适合高并发、多人同时使用

6. **PWA 的认证体验有限**
   - 首次连接需要弹窗登录
   - 密码只保存在内存中，关闭页面后需要重新输入
   - 无法像原生 App 一样自动携带凭证

7. **没有原生 iOS / 鸿蒙 App**
   - 目前用 PWA 覆盖 iPhone / 鸿蒙
   - 体验上不如原生 App，且无法上架 App Store / 华为应用市场

8. **Android APK 签名不固定**
   - CI 每次构建生成新 keystore
   - 用户升级需要先卸载旧版，会丢失本地设置

## 二、拓展方向

### 1. 去掉“电脑必须开机”的依赖
- 把 DSH 部署到 **云服务器 / VPS**
- 例如：
  - Oracle Cloud 免费层
  - 腾讯云 / 阿里云轻量服务器
- 这样服务 7×24 在线，电脑可以关机

### 2. 固定域名 + 浏览器直连
- 升级为 **Cloudflare Named Tunnel**
- 搭配自己的域名：
  ```
  https://dsh.yourdomain.com
  ```
- 这样：
  - 域名固定
  - 浏览器可以直接访问
  - PWA 也可以直接用固定域名，不再依赖随机隧道

### 3. 降低用户部署门槛
- 提供 **Docker 一键部署**
- 或提供 **云服务器一键安装脚本**
- 让普通用户也能快速拥有自己的 DSH 服务

### 4. 改进 PWA 认证体验
- 在认证代理里增加 **PWA 登录桥**
  - 让 PWA 通过 API 完成登录
  - 自动携带凭证，不需要每次弹窗
- 或使用 **WebAuthn / 设备绑定** 提升安全性

### 5. 原生 App 化（可选）
- 如果以后需要上架：
  - iOS：注册 Apple Developer，打包 IPA
  - 鸿蒙：用 DevEco 打包 HAP
- 当前 PWA 方案已覆盖基本使用，原生化不是必须

### 6. 多人 / 多租户（远期）
- 当前架构是“一人一服务”
- 如果以后想给很多人共用，需要：
  - 多用户账号体系
  - 资源隔离
  - 计费 / 配额
- 这会改变项目性质，属于较大重构

## 三、建议优先级

| 优先级 | 方向 | 说明 |
|---|---|---|
| 🔴 高 | 云服务器 / VPS 部署 | 解决“电脑必须开机” |
| 🔴 高 | Cloudflare Named Tunnel + 自有域名 | 解决“固定域名直连” |
| 🟡 中 | Docker 一键部署 | 降低用户门槛 |
| 🟡 中 | PWA 登录桥 | 改善认证体验 |
| 🟢 低 | 原生 iOS / 鸿蒙 | 按需再做 |
| 🟢 低 | 多租户 | 远期再说 |
